# SK매직 챗봇 교차검증 결과

AS-IS PPT 100장, 1차 PDF와 Figma의 흐름도·화면을 대조했습니다. 1차 PDF 15종 30페이지를 확인했고, DRM이 적용된 배송 변경 PDF는 같은 버전의 Draw.io와 AS-IS 30–31장으로 확인했습니다. 18–50의 개별 설계 PDF는 자료 범위에 없었습니다. 이 구간은 해당 PPT와 Figma를 대조하고 공통 절차에 1차 PDF를 참조했습니다.

## 챗봇 고객 범위와 콜봇 근거

- 현재 챗봇은 개인·개인사업자 고객 업무를 제공합니다. 법인 전용 조회, 견적, 계약 및 서류 경로는 이번 버전의 범위에서 제외했습니다. 법인 문의에는 지원 고객 범위를 안내합니다.
- AS 접수 취소 설계서 1쪽은 취소 이력에 챗봇 채널 `AICCChatbot`과 고객이 고른 사유를, 콜봇 채널 `AICCCallbot`과 고정 사유 `고객취소`를 기록하도록 명시합니다.
- 차수 계획의 ‘차수현황’ E7·E14·E16·E17은 06 제휴카드 문의, 13 서비스 접수 정보 확인, 15 서비스 취소, 16 배송 설치 문의를 ‘챗봇/콜봇’으로 명시합니다. 나머지 1차 항목에는 ‘챗봇’이 표기되어 있습니다. 이 HTML은 1차 채팅을 구현합니다.
- 공통 설계서 1쪽은 IVR을 유입 채널로 표시하고, 4쪽은 상담사 이관과 전화 예약을 구분합니다. 50번 구독 체결 심사는 상담사가 먼저 전화하는 업무로 별도 검토에 표시되어 있습니다.

## 통합 실행 검증

- 50개 업무를 기본 진입점에서 실행하고 888개 상태의 1,617회 전환에서 멈춤, 예외 및 예시 입력 오류가 없는지 확인했습니다.

## 상담 화면 보완

- 50개 흐름의 선택 화면을 살펴보고 제품·계약·접수·주문 목록, 방문·배송·회수일, 방문 주소, 문서와 발송 방법, 선납 기간, 동의 항목을 선택 카드나 목록으로 구성했습니다. 계약과 주문의 모델명·상태 등은 해당 선택지 안에서 확인합니다. 조회 결과는 정보 영역에 모아 표시합니다.
- 고장 상담과 AS 방문 접수에서 제품 카드와 증상 대분류·중분류·소분류를 선택합니다. 제품명이나 증상을 직접 입력할 수도 있습니다. 고장 상담에서 방문 접수로 이어지면 선택한 제품과 증상을 재사용합니다. 비데 노즐 예는 고장접수 설계서 2쪽을 반영했고, 다른 선택지는 시연용 분류입니다.
- 고객이 조회 성공·실패나 처리 상태를 고르던 단계를 없앴습니다. 고객이 입력한 주문·계약 정보나 해당 날짜에 따라 화면이 이어집니다. 상담 목적, 계약, 납부수단, 발송 방법처럼 고객이 결정하는 항목은 선택지로 표시합니다.
- 인증번호는 요청과 재요청마다 새로 만들고 별도의 인증 문자에서 확인합니다. 이전 번호는 재요청 후 사용할 수 없습니다. 값 채우기 버튼은 하단 입력창의 보조 기능으로 유지합니다.
- 입력값에 따른 배송 조회 실패·제한, PASS 확인, 금융정보 마스킹은 별도로 검증했습니다.
